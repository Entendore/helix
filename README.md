# Helix — hybrid-ECS + wgpu engine (bootstrap)

Generated by `helix-bootstrap.sh` from the Helix spec (`docs/SPEC.md`).

## Layout

```
crates/
  helix-core    math, hash, config, cvars               (Tier 0)
  helix-ecs     World, scheduler, modules, events,
                rng, registry, save                     (Core profile)
  helix-assets  Vertex/MeshId/DrawCall, mesh map        (Handle bridge)
  helix-scene   RON level loader + level-authorable comps
  helix-sim     the demo game's simulation              (NO wgpu/winit — CI-proved)
  helix-render  wgpu renderer, render thread, HDR+ACES post, frame graph
  helix-app     windowed engine facade + thin bin
  helix-testkit fixtures, gates, manifest                (dev-only)
docs/SPEC.md   the specification
assets/        level.ron, bindings.ron, helix.ron
scenarios/     headless scenario docs ([H] suite input)
tests/         manifest.ron + recorded digest fixtures (tests/digests/)
```

## Run

```bash
cargo run -p helix-app --release     # WASD/arrows move the cube; ` = console
```

Console (`` ` `` in debug builds): `set render.scale 0.5`, `set render.exposure 1.5`,
`hash`, `save`, `load`, `list`, `get gpu.tier`.

## Test

```bash
cargo test        # 1st run RECORDS digest fixtures and asks to re-run
cargo test        # 2nd run VERIFIES — determinism is now load-bearing
UPDATE_GOLDENS=1 cargo test   # deliberately re-record after intended changes
```

The [H] suite simulates the level headlessly (no GPU) and pins a digest per
scenario: any change to sim behavior, storage semantics, or the RNG stream
fails until fixtures are deliberately regenerated. CI runs the two-run
pattern automatically.

Backend override (as everywhere in wgpu): `WGPU_BACKEND=gl|vulkan|metal|dx12`.
